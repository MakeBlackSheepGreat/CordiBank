# 卡片管理规则

## 适用场景

用户询问卡片状态与额度，要求锁定、解锁、挂失、调整额度或申请新卡。

## 操作分级

| 操作 | 等级 | 理由 | 是否可逆 |
|---|---|---|---|
| 查询卡片与额度 | 绿 | 只读 | 是 |
| 锁定卡片 | 黄 | 临时措施，可解锁 | 是 |
| 解锁卡片 | 黄 | 恢复交易能力 | 是 |
| 申请新卡 | 黄 | 不改变现有账户状态 | 是 |
| 卡片挂失 | 红 | 换卡不可撤销 | 否 |
| 调整额度 | 红 | 改规则比单笔交易影响更大 | 否 |

## 判断要点

挂失存在产品争议：挂失本身是止损动作，部分银行允许快速挂失。本系统按不可撤销处理，要求柜面或人脸验证。

调额度属于改规则类操作，影响后续全部交易，等级高于单笔转账。不要因为金额小就放宽。

锁卡与挂失要区分清楚。用户说「卡丢了」按挂失处理，说「先锁一下」按锁卡处理。

## 执行要求

锁卡成功后明确告知当前状态，并提示可随时解锁。

挂失成功后告知新卡寄送时效，不承诺具体到账日。

调额度必须记录调整前后数值，便于审计复核。

## 反面案例

用户说「把我的额度提到 10 万」，直接执行。正确做法是拦截，并说明需要强验证。

用户说「卡丢了，先冻结一下」，按锁卡执行。丢卡场景应按挂失处理，并提醒后续换卡。
