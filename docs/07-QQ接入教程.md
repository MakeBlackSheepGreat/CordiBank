# QQ 接入教程（OneBot v11 HTTP 上报）

QQ 没有对普通用户开放的官方机器人 API；本项目的 QQ 渠道走社区通用的 OneBot v11 协议，由 NapCat 或 Lagrange 等实现把 QQ 消息以 HTTP 方式上报给运行时。以下以 NapCat 为例（Lagrange 配置项同名，步骤一致）。

## 1. 部署 OneBot 实现（NapCat）

1. 下载 NapCat（Windows 可用 NapCat.Shell 一键包），用一个小号 QQ 登录（机器人号，不要用主力号）。
2. 在 NapCat 的 WebUI 里创建「HTTP 服务器」与「HTTP 客户端」两段配置：
   - **HTTP 服务器**（NapCat 提供的 OneBot API，供运行时调用发消息）：监听如 `http://127.0.0.1:3000`，可设 Access Token。
   - **HTTP POST 上报**（NapCat 主动把收到的消息推给运行时）：URL 填 `http://127.0.0.1:8123/channel/onebot/incoming`，勾选「上报消息事件」。
3. 两侧的 Access Token 保持一致，并同时配置到运行时环境变量（见下一步）。

## 2. 配置运行时

```bash
# OneBot HTTP API 基址（NapCat 的 HTTP 服务器地址）
set CORDIBANK_CHANNEL_QQ_API=http://127.0.0.1:3000
# 上报与送回共用的 Bearer 令牌（与 NapCat 的 Access Token 相同，可选）
set CORDIBANK_CHANNEL_QQ_TOKEN=你的令牌
# 启动运行时
node runtime/dist/server.js
```

## 3. 验证

1. 用另一个 QQ 号给机器人号发私聊消息「查询当前余额」，机器人应回复真实余额。
2. 群聊里 @机器人 或直接发消息（取决于 NapCat 的上报配置），回复走 `send_group_msg` 送回。
3. 打开网页控制台右侧「渠道接入」卡，QQ 一行应变为「使用中」并显示消息计数与最近收发留痕。

## 行为细节

- 私聊回复：`POST <API>/send_private_msg`，参数 `{user_id, message}`。
- 群聊回复：`POST <API>/send_group_msg`，参数 `{group_id, message}`。
- 送回请求带 `Authorization: Bearer <CORDIBANK_CHANNEL_QQ_TOKEN>`（令牌非空时）。
- 上报体内的 `token` 字段（如与运行时配置不一致）会被直接拒绝，不进入智能体。
- OneBot 的消息段数组（`raw_message` 为数组）会自动拼接出纯文本。
- 会话键为 `qq-<QQ号>`：同一 QQ 号在私聊与群聊共享同一会话，跨号互不串话。
