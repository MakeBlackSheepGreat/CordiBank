# QQ 接入教程（官方机器人开放平台）

QQ 渠道走 QQ 官方机器人开放平台，凭证式接入：在开放平台创建机器人拿到 AppID 与 AppSecret，运行时用这两项换 `access_token`，再经 WebSocket 长连接收事件、经 OpenAPI 发消息。

接入全程在应用内「设置 → IM 渠道 → 渠道接入向导」完成，不需要双击任何 bat，不需要打开第三方协议端，也不需要命令行。

## 一、在开放平台创建机器人

1. 打开 [QQ 开放平台机器人管理端](https://q.qq.com/qqbot/)，用手机 QQ 扫码登录。
2. 创建机器人，填写名称、头像与简介并提交。
3. 在机器人的开发设置里取 **AppID** 与 **AppSecret**。AppSecret 只在生成时展示一次，需自行保存。
4. 在功能配置里开启群聊与单聊能力，事件订阅勾选群 @机器人 与单聊消息，订阅位为 `GROUP_AND_C2C_EVENT`（`1 << 25`）。

## 二、向导内四步

打开「设置 → IM 渠道 → 渠道接入向导」，QQ 卡片内是 AppID、AppSecret 两个输入框与「保存并校验」「连接 QQ」「断开」「打开开放平台」四个按钮。

1. **填 AppID / AppSecret**：粘贴上一步取得的两项；点「打开开放平台」可直达机器人管理端。
2. **保存并校验**：向导用这两项真调 `POST https://api.bot.qq.com/app/getAppAccessToken`，换到 `access_token` 才算通过；校验失败不落盘，界面直接报错。
3. **连接 QQ**：用已保存凭据取 token、取网关、建 WebSocket 长连接，收到 `READY` 视为连接成功。
4. **验证**：把机器人拉进群，在群里 @机器人 发「查询当前余额」；或直接在单聊里发消息。

落盘位置：`store/settings.json` 的 `channels.qqBotAppId` 与 `channels.qqBotAppSecret`。点「断开」结束长连接，已保存凭据保留，再次点「连接 QQ」即可恢复。

## 三、配置项与环境变量

| 配置项（config.ts） | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `channelQqBotAppId` | `CORDIBANK_CHANNEL_QQBOT_APP_ID` | 空 | 开放平台机器人 AppID |
| `channelQqBotAppSecret` | `CORDIBANK_CHANNEL_QQBOT_APP_SECRET` | 空 | 开放平台机器人 AppSecret |
| `channelQqBotApiBase` | `CORDIBANK_CHANNEL_QQBOT_API` | `https://api.bot.qq.com` | 开放平台接口基址 |

```powershell
$env:CORDIBANK_CHANNEL_QQBOT_APP_ID="你的 AppID"
$env:CORDIBANK_CHANNEL_QQBOT_APP_SECRET="你的 AppSecret"
$env:CORDIBANK_CHANNEL_QQBOT_API="https://api.bot.qq.com"
node runtime/dist/server.js
```

「设置 → IM 渠道 → QQ」的两个输入框写同一份配置，保存即热生效，不需要重启进程。

## 四、协议细节

取凭证：

- `POST /app/getAppAccessToken`，body `{appId, clientSecret}`，返回 `{access_token, expires_in}`。
- 有效期约 2 小时，客户端提前 300 秒刷新。
- 鉴权头格式为 `Authorization: QQBot <access_token>`。

错误回包：HTTP 200 但 body 是 `{code, message}`，运行时按 `code` 判定成败，不只看状态码。

网关与长连接：

- `GET /gateway` 返回 `{url}`。
- 连上先收 `op 10 HELLO`，带 `heartbeat_interval`；客户端发 `op 2 IDENTIFY`，载荷含 `token`、`intents = 1 << 25`（`GROUP_AND_C2C_EVENT`）、`shard [0, 1]`。
- 收到 `op 0 t=READY` 视为连接成功。
- `op 1` 心跳、`op 11` ACK；`op 7` / `op 9` 触发重连，指数退避 3 秒起、上限 60 秒。

收消息：事件名 `GROUP_AT_MESSAGE_CREATE`（群 @机器人）、`C2C_MESSAGE_CREATE`（单聊）、`GROUP_MSG_RECEIVE` 等，正文里的 @ 占位符剔除后交给银行 Agent。

发消息：

- 群聊 `POST /v2/groups/{group_openid}/messages`，单聊 `POST /v2/users/{user_openid}/messages`。
- body `{content, msg_type: 0, msg_id, msg_seq}`；被动回复带 `msg_id`，同一 `msg_id` 的第 N 次回复用递增的 `msg_seq`。

WebSocket 用 Node 24 内置全局 WebSocket，未新增任何依赖。

## 五、常见错误

| 界面或日志现象 | 原因 | 处理 |
| --- | --- | --- |
| `QQ 机器人凭证校验失败：机器人不存在（code 10004）` | AppID 不存在、已删除或填错 | 回开放平台核对 AppID，重新粘贴后点「保存并校验」 |
| `AppID 或 ClientSecret 不正确（code 10003）` | AppSecret 填错、已重置或与 AppID 不配对 | 开放平台重新生成 AppSecret，两项一起重填 |
| 长连接建立后立即被服务端断开 | 机器人未开通对应事件订阅，intents 无权限 | 在开放平台补齐群聊 / 单聊事件订阅后重连 |
| 反复重连，间隔从 3 秒逐次拉长 | 收到 `op 7` / `op 9`，服务端要求重连 | 运行时按指数退避自动重连，上限 60 秒 |

## 六、第三方 OneBot 桥（可选兼容路径）

自建协议端时仍可走 OneBot v11 HTTP 上报，与官方机器人并行存在，互不影响。以下以 Lagrange 为例，配置项同名。

1. 协议端起一个「HTTP 服务器」（OneBot API，供运行时调用发消息），监听如 `http://127.0.0.1:3000`，可设 Access Token。
2. 协议端再配「HTTP POST 上报」：URL 填 `http://127.0.0.1:8123/channel/onebot/incoming`，勾选「上报消息事件」。
3. 两侧令牌保持一致，配到运行时的 `CORDIBANK_CHANNEL_QQ_TOKEN`；服务器基址配到 `CORDIBANK_CHANNEL_QQ_API`。

```bash
# OneBot HTTP API 基址（协议端 HTTP 服务器地址）
set CORDIBANK_CHANNEL_QQ_API=http://127.0.0.1:3000
# 上报与送回共用的 Bearer 令牌（与协议端 Access Token 相同，可选）
set CORDIBANK_CHANNEL_QQ_TOKEN=你的令牌
# 启动运行时
node runtime/dist/server.js
```

OneBot 兼容桥只在环境变量里配置，设置面板的渠道字段仍只针对 QQ 官方机器人。

行为细节：

- 私聊回复：`POST <API>/send_private_msg`，参数 `{user_id, message}`。
- 群聊回复：`POST <API>/send_group_msg`，参数 `{group_id, message}`。
- 送回请求带 `Authorization: Bearer <CORDIBANK_CHANNEL_QQ_TOKEN>`（令牌非空时）。
- 上报体内的 `token` 字段与运行时配置不一致时直接拒绝，不进入智能体。
- OneBot 的消息段数组（`raw_message` 为数组）自动拼接出纯文本。
- 会话键为 `qq-<QQ号>`：同一 QQ 号在私聊与群聊共享同一会话，跨号互不串话。
- 渠道状态里这一路名为 `onebot`，与官方机器人的 `qq` 分开计数。
