# 部署说明

这份文档说明怎么把系统跑起来，包括环境准备、启动步骤、测试验证与常见问题。

## 一、环境要求

| 软件 | 版本 | 用途 |
|---|---|---|
| Node.js | 22 或更高 | 运行后端与构建前端 |
| npm | 10 或更高 | 安装前端依赖 |

不需要数据库，不需要 Docker，不需要 Python。

国内网络建议先换镜像源，一条命令。

```powershell
npm config set registry https://registry.npmmirror.com
```

验证。

```powershell
node -v
npm -v
```

## 二、启动后端

后端位于 `runtime/`，直接用 Node 执行 TypeScript，无编译步骤。

```powershell
cd runtime
npm install
npm start
```

默认监听 `http://127.0.0.1:8123`。

启动成功会看到能力清单与工具数量。

### 环境变量

全部可选，不配也能跑。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `RUNTIME_PORT` | `8123` | 监听端口 |
| `CORDIBANK_STORE_DIR` | `./data` | 数据目录，账户与审计落在这里 |
| `LLM_API_KEY` | 空 | 模型密钥，不配则走纯规则模式 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | 模型接口地址 |
| `LLM_MODEL` | `deepseek-flash` | 模型名 |
| `LLM_THINKING` | `on` | 意图解析可设为 `off` 省 token |

配置示例。

```powershell
$env:LLM_API_KEY="你的密钥"
$env:LLM_MODEL="deepseek-flash"
cd runtime
npm start
```

不配密钥时系统进入规则模式。六个场景仍可演示，只是口语化表达识别率下降。

## 三、启动前端

前端位于 `web/`，Vue 3 加 Vite。

```powershell
cd web
npm install
npm run dev
```

开发模式打开 `http://127.0.0.1:5173`，请求自动代理到后端。

生产构建。

```powershell
npm run build
```

构建产物在 `web/dist/`，可由后端静态托管，也可单独部署到任意静态服务器。

## 四、外部服务

四个 MCP 服务位于 `mcp/`，独立进程，标准输入输出通信。

| 服务 | 工具数 | 用途 |
|---|---|---|
| `fx-server.mjs` | 3 | 汇率与跨境 |
| `risk-server.mjs` | 3 | 反欺诈与征信 |
| `catalog-server.mjs` | 3 | 理财费率与适当性 |
| `gift-server.mjs` | 4 | 生日礼遇预订 |

首次启动后端时自动注入服务清单到数据目录，随后自动握手注册工具。

自检。

```powershell
cd mcp
node selftest.mjs
```

输出四个服务各三个样例结果即为正常。

## 五、渠道

### 通用 webhook

```js
import { startWebhookChannel } from "./channels/generic-webhook.mjs";

startWebhookChannel({
  port: 18140,
  chat: (sessionId, text) => agent.chat(sessionId, text),
});
```

请求与响应。

```
POST /
{ "userId": "u-001", "text": "查一下余额" }

200
{ "reply": "可用余额 38642.50 元", "level": "green", "auditSeq": 1 }
```

### 企业微信

三个环境变量。

```powershell
$env:WECOM_CORP_ID="填写企业标识"
$env:WECOM_AGENT_ID="填写应用标识"
$env:WECOM_SECRET="填写应用密钥"
```

无凭据时用 `dryRun` 模式，脚本打印要发的包，不真发。

## 六、测试验证

后端测试分四层，共 91 项。

```powershell
cd runtime
npx vitest run
```

只跑某一层。

```powershell
npx vitest run tests/bank-agent.test.ts    # 单元与集成
npx vitest run tests/swarm.test.ts         # 蜂群协同
npx vitest run tests/agent-loop.test.ts    # 真实模型循环
```

红队统计。

```powershell
curl -X POST http://127.0.0.1:8123/rpc \
  -H "Content-Type: application/json" \
  -d '{"method":"bank.agent.redteam","params":[]}'
```

返回拦截率与误拦率。

## 七、接口

后端单入口 `/rpc`，POST，body 是 `{ method, params }`。

| 方法 | 参数 | 说明 |
|---|---|---|
| `bank.agent.chat` | `[会话, 文本]` | 单流程对话 |
| `bank.agent.swarm` | `[会话, 文本]` | 蜂群协同对话，返回协作轨迹 |
| `bank.agent.confirm` | `[会话, 令牌]` | 确认待办 |
| `bank.agent.cancel` | `[会话]` | 取消待办 |
| `bank.agent.state` | `[]` | 账户快照 |
| `bank.agent.audit` | `[会话?, 条数?]` | 审计记录与链校验 |
| `bank.agent.tools` | `[]` | 工具清单与来源 |
| `bank.agent.model` | `[]` | 模型配置与工具数 |
| `bank.agent.redteam` | `[]` | 红队统计 |
| `bank.agent.reset` | `[]` | 重置演示数据 |

示例。

```powershell
curl -X POST http://127.0.0.1:8123/rpc -H "Content-Type: application/json" -d '{"method":"bank.agent.swarm","params":["s1","转给小王 100 元"]}'
```

## 九、常见问题

### 启动报端口占用

换端口。

```powershell
$env:RUNTIME_PORT="8124"
npm start
```

### 前端连不上后端

确认后端已启动，且 `web/vite.config.ts` 的代理目标端口一致。

### 安装依赖很慢

确认镜像源已切换。

```powershell
npm config get registry
```

### 模型调用超时

检查密钥与网络。不配密钥也能演示，系统会自动走规则模式。

### 审计链校验失败

说明数据文件被手工改过。运行 `bank.agent.reset` 重置演示数据。

## 十、部署到服务器

生产部署建议三步。

一，前端构建产物交给 Nginx 静态托管。

二，后端用 systemd 或 pm2 常驻，环境变量写在服务配置里。

三，MCP 服务由后端按需拉起，不需要单独配置进程。

注意两点：数据目录要有写权限；审计文件只追加，不要放在临时目录。
