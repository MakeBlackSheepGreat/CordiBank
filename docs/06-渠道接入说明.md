# 渠道接入说明

CordiBank 通过渠道适配层把同一套银行智能体暴露给不同入口。所有渠道共用权限分级、注入防御与审计哈希链，消息留痕可在网页控制台右侧「渠道接入」卡与 `channel.hub.status` 回包中查看。

## 渠道一览

| 渠道 | 接入方式 | 状态判定 |
| --- | --- | --- |
| web | 网页控制台直连 RPC 与 SSE 流式 | 内置启用 |
| desktop | Windows 桌面壳内嵌同一控制台 | 内置启用 |
| wechat（微信） | 腾讯 ilink 官方接口，向导扫码后长轮询收发 | `channelWechatBotToken` 非空为已配置，否则未配置 |
| qq（QQ） | QQ 官方机器人开放平台，AppID + AppSecret 换 token 后 WebSocket 长连接收发 | `channelQqBotAppId` 非空为已配置，否则未配置 |
| onebot（OneBot v11 兼容桥） | 第三方 OneBot 实现的 HTTP 上报，回复经协议端 HTTP API 送回 | `channelQqApiUrl` 非空为已配置，否则未配置 |
| dingtalk（钉钉） | 企业内部机器人官方 HTTP 回调，sign 加签验签 | `channelDingtalkSecret` 非空为已配置，否则未配置 |
| feishu（飞书） | 事件订阅官方回调，challenge 握手 + tenant_access_token 送回 | `channelFeishuAppId` 非空为已配置，否则未配置 |
| webhook（通用桥） | 通用 HTTP 上报，由桥接程序送回 | 无凭据，即刻可用 |

## 渠道接入向导

微信与 QQ 的接入都在应用内「设置 → IM 渠道 → 渠道接入向导」完成，不需要双击任何 bat、不需要打开第三方协议端、不需要命令行。

内置能力插件 `channel-wizard`（服务名 `channel.wizard`）提供七个方法：`state` 读取整体状态，微信侧 `wechatQr` / `wechatPoll` / `wechatLogout`，QQ 侧 `qqSave` / `qqConnect` / `qqDisconnect`。

QQ 卡片内是 AppID、AppSecret 两个输入框与「保存并校验」「连接 QQ」「断开」「打开开放平台」四个按钮。官方机器人是凭证式接入，二维码登录只属于微信 ilink。

## 微信（腾讯 ilink 官方接口）

扫码接入，四步完成。

1. 打开「设置 → IM 渠道 → 渠道接入向导」，点微信「扫码接入」。
2. 后端调用 `POST https://ilinkai.weixin.qq.com/ilink/bot/get_bot_qrcode?bot_type=3` 取码，界面渲染二维码。
3. 手机微信扫码；后端以 `GET ilink/bot/get_qrcode_status` 长轮询登录态，服务端挂住 35 秒，超时返回 `wait`。
4. 登录确认后服务端下发 `bot_token` 与 `ilink_bot_id`，运行时落盘并启动收发循环。

落盘位置：`store/settings.json` 的 `channels.wechatToken`（机器人令牌）与 `channels.wechatAccount`（机器人账号）。点「退出接入」清空这两项并停掉收发循环。

环境变量可覆盖同名字段：

```powershell
$env:CORDIBANK_CHANNEL_WECHAT_TOKEN="ilink 下发的 bot_token"
$env:CORDIBANK_CHANNEL_WECHAT_ACCOUNT="ilink 下发的 ilink_bot_id"
$env:CORDIBANK_CHANNEL_WECHAT_BASE="https://ilinkai.weixin.qq.com"
```

`CORDIBANK_CHANNEL_WECHAT_BASE` 默认 `https://ilinkai.weixin.qq.com`；登录回包带回专属基址时以回包为准。

收发协议：

- 入站：`POST ilink/bot/getupdates` 长轮询，带 `get_updates_buf` 游标，游标随每批回包推进。
- 出站：`POST ilink/bot/sendmessage`，必须原样带回入站消息的 `context_token`。
- 每条请求带 `AuthorizationType: ilink_bot_token`、`iLink-App-Id`、`iLink-App-ClientVersion` 与随机 `X-WECHAT-UIN`；令牌非空时再带 `Authorization: Bearer <bot_token>`。

## QQ（官方机器人开放平台）

凭证式接入，四步完成，全程在应用内，不需要双击任何 bat、不需要打开第三方协议端、不需要命令行。

1. 在 [QQ 开放平台](https://q.qq.com/qqbot/) 创建机器人，取 AppID 与 AppSecret。
2. 打开「设置 → IM 渠道 → 渠道接入向导」，QQ 卡片填这两项，点「保存并校验」。向导真调 `POST /app/getAppAccessToken` 换 `access_token`，校验通过才落盘，失败直接报错不落盘。
3. 点「连接 QQ」。运行时取 token、取网关、建 WebSocket 长连接，收到 `READY` 视为连接成功。
4. 群里 @机器人 或单聊发消息验证。

落盘位置：`store/settings.json` 的 `channels.qqBotAppId` 与 `channels.qqBotAppSecret`。点「断开」结束长连接，凭据保留；再点「连接 QQ」恢复。

环境变量可覆盖同名字段：

```powershell
$env:CORDIBANK_CHANNEL_QQBOT_APP_ID="开放平台机器人的 AppID"
$env:CORDIBANK_CHANNEL_QQBOT_APP_SECRET="开放平台机器人的 AppSecret"
$env:CORDIBANK_CHANNEL_QQBOT_API="https://api.bot.qq.com"
```

| 配置项 | 环境变量 | 默认值 |
| --- | --- | --- |
| `channelQqBotAppId` | `CORDIBANK_CHANNEL_QQBOT_APP_ID` | 空 |
| `channelQqBotAppSecret` | `CORDIBANK_CHANNEL_QQBOT_APP_SECRET` | 空 |
| `channelQqBotApiBase` | `CORDIBANK_CHANNEL_QQBOT_API` | `https://api.bot.qq.com` |

收发协议：

- 取凭证：`POST /app/getAppAccessToken`，body `{appId, clientSecret}`，返回 `{access_token, expires_in}`，有效期约 2 小时，客户端提前 300 秒刷新。
- 鉴权头：`Authorization: QQBot <access_token>`。
- 错误回包：HTTP 200 但 body 是 `{code, message}`，按 `code` 判定成败。
- 网关：`GET /gateway` 返回 `{url}`；`op 10 HELLO` 带 `heartbeat_interval`，客户端发 `op 2 IDENTIFY`（`token`、`intents = 1 << 25`、`shard [0, 1]`），收到 `op 0 t=READY` 视为连接成功。
- 心跳与重连：`op 1` 心跳、`op 11` ACK；`op 7` / `op 9` 触发重连，指数退避 3 秒起、上限 60 秒。
- 入站事件：`GROUP_AT_MESSAGE_CREATE`（群 @机器人）、`C2C_MESSAGE_CREATE`（单聊）、`GROUP_MSG_RECEIVE` 等，@ 占位符剔除后交给银行 Agent。
- 出站：`POST /v2/groups/{group_openid}/messages` 与 `POST /v2/users/{user_openid}/messages`，body `{content, msg_type: 0, msg_id, msg_seq}`；被动回复带 `msg_id`，同一 `msg_id` 的第 N 次回复用递增的 `msg_seq`。
- WebSocket 用 Node 24 内置全局 WebSocket，未新增依赖。

常见错误：`10004` 机器人不存在，`10003` AppID 或 ClientSecret 不正确，intents 无权限时服务端建立连接后直接断开。

## OneBot v11 兼容桥（第三方桥，可选）

自建协议端时走 OneBot v11 HTTP 上报，与官方机器人并行，状态里单独记为 `onebot`。

1. 协议端起「HTTP 服务器」（OneBot API，供运行时发消息），如 `http://127.0.0.1:3000`，可设 Access Token。
2. 协议端再配「HTTP POST 上报」，URL 填 `http://127.0.0.1:8123/channel/onebot/incoming`，勾选上报消息事件。
3. 两侧令牌一致，配到 `CORDIBANK_CHANNEL_QQ_TOKEN`；服务器基址配到 `CORDIBANK_CHANNEL_QQ_API`。

```powershell
$env:CORDIBANK_CHANNEL_QQ_API="http://127.0.0.1:3000"
$env:CORDIBANK_CHANNEL_QQ_TOKEN="协议端的 Access Token"
```

- 入站：上报体内的 `token` 与运行时配置不一致直接拒绝；消息段数组自动拼接为纯文本。
- 出站：`POST <API>/send_private_msg`（`{user_id, message}`）与 `POST <API>/send_group_msg`（`{group_id, message}`），令牌非空时带 `Authorization: Bearer <CORDIBANK_CHANNEL_QQ_TOKEN>`。
- 会话键为 `qq-<QQ号>`，同一 QQ 号在私聊与群聊共享会话。

## 钉钉（企业内部机器人官方回调）

1. 钉钉开放平台创建企业内部机器人，接收消息模式选「HTTP 回调」，地址指向 `http://<公网或内网穿透>:8123/channel/dingtalk/incoming`。
2. 环境变量配置加签密钥：`CORDIBANK_CHANNEL_DINGTALK_SECRET=<机器人的加签密钥>`。
3. 运行时按官方算法验签：`sign = base64(HMAC-SHA256(appSecret, timestamp + "\n" + appSecret))`，时间偏差容忍 ±1 小时；验签失败返回 `ACCESS_DENIED`。
4. 回复走官方同步回包：HTTP 响应体即 `{"msgtype":"text","text":{"content":"…"}}`，无需额外调用发送接口；会话键为 `dingtalk-<staffId>`。

## 飞书（事件订阅官方回调）

1. 飞书开放平台创建企业自建应用，事件订阅请求地址指向 `http://<公网>:8123/channel/feishu/incoming`，订阅 `im.message.receive_v1`。
2. 环境变量：`CORDIBANK_CHANNEL_FEISHU_TOKEN`（事件订阅的 Verification Token，可选但建议）、`CORDIBANK_CHANNEL_FEISHU_APP_ID`、`CORDIBANK_CHANNEL_FEISHU_APP_SECRET`、可选 `CORDIBANK_CHANNEL_FEISHU_API_BASE`（默认 https://open.feishu.cn）。
3. URL 验证：运行时对 `url_verification` 事件原样返回 `challenge`（官方握手格式）。
4. 消息事件：进入银行 Agent 会话后，运行时用 `tenant_access_token`（`app_id`+`app_secret` 换取）调用官方 `im/v1/messages` 送回文本；群聊 @机器人 的占位符会自动剔除；会话键为 `feishu-<chat_id>`。

## 通用 webhook 桥

桥接程序把用户消息 POST 到运行时，运行时同步返回智能体回复：

```bash
curl -X POST http://127.0.0.1:8123/channel/webhook/incoming \
  -H "content-type: application/json" \
  -d '{"channel":"wechat","from":"user-9527","text":"查询当前余额"}'
```

回包：

```json
{"ok":true,"result":{"ok":true,"channel":"wechat","from":"user-9527","reply":"当前余额 38642.50 元"}}
```

会话键为 `webhook-<channel>-<from>`，不同用户互不串话。回复由桥接程序负责送回原渠道。

## 安全约束

- 各渠道令牌 / 签名不匹配直接拒绝（`ACCESS_DENIED`），不进入智能体。
- 消息正文上限 2000 字符，超长截断；最近 50 条收发消息留痕。
- 所有渠道消息与回复经同一套注入防御（正则守卫 + 语义分类器）与审计哈希链，与网页入口一致。
