# 渠道接入说明

CordiBank 通过渠道适配层把同一套银行智能体暴露给不同入口。所有渠道共用权限分级、注入防御与审计哈希链，消息留痕可在网页控制台右侧「渠道接入」卡与 `channel.hub.status` 回包中查看。

## 渠道一览

| 渠道 | 接入方式 | 状态 |
| --- | --- | --- |
| web | 网页控制台直连 RPC 与 SSE 流式 | 内置启用 |
| desktop | Windows 桌面壳内嵌同一控制台 | 内置启用 |
| onebot（QQ） | OneBot v11 HTTP 上报，私聊与群聊 | 配置后启用 |
| webhook（微信等） | 通用 HTTP 上报，由桥接程序送回 | 即刻可用 |

## Webhook 桥（微信等通用桥）

桥接程序把用户消息 POST 到运行时，运行时同步返回智能体回复：

```bash
curl -X POST http://127.0.0.1:8123/channel/webhook/incoming \
  -H "content-type: application/json" \
  -d '{"channel":"wechat","from":"user-9527","text":"查询当前余额"}'
```

回包：

```json
{"ok":true,"result":{"ok":true,"channel":"wechat","from":"user-9527","reply":"当前余额 38642.50 元"}}
```

会话键为 `webhook-<channel>-<from>`，不同用户互不串话。回复由桥接程序负责送回原渠道（如企业微信应用消息 API）。

## QQ（OneBot v11 HTTP 上报）

1. 部署 NapCat 或 Lagrange 等 OneBot v11 实现，开启 HTTP 上报，目标地址指向运行时：
   `http://127.0.0.1:8123/channel/onebot/incoming`
2. 配置送回用的 QQ API 地址与可选令牌（环境变量）：
   - `CORDIBANK_CHANNEL_QQ_API`：OneBot HTTP API 基址（如 `http://127.0.0.1:3000`）
   - `CORDIBANK_CHANNEL_QQ_TOKEN`：上报与送回共用的 Bearer 令牌（可选）
3. 私聊与群聊消息自动走对应 `send_private_msg` / `send_group_msg` 送回；会话键为 `qq-<QQ号>`。

## 安全约束

- 上报令牌不匹配直接拒绝（`ACCESS_DENIED`），不进入智能体。
- 消息正文上限 2000 字符，超长截断；最近 50 条收发消息留痕。
- 所有渠道消息与回复经同一套注入防御（正则守卫 + 语义分类器）与审计哈希链，与网页入口一致。
