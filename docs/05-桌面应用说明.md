# 桌面应用

CordiBank 蜂群银行助手的 Windows 桌面版本。把后端服务与前端界面封装成一个安装包，评委下载安装后双击即可运行，不需要配置 Node 环境。

## 一、成品

| 文件 | 大小 | 说明 |
|---|---|---|
| `CordiBank 蜂群银行助手-1.0.0-x64.exe` | 120 MB | NSIS 安装包，可选安装路径，创建桌面与开始菜单快捷方式 |
| `CordiBank 蜂群银行助手-1.0.0-x64.exe.blockmap` | 130 KB | 增量更新用的分块校验文件 |

体积主要来自 Electron 运行时与 Chromium 内核。

## 二、安装

双击安装包，按提示操作。默认安装到当前用户目录，无需管理员权限。

安装完成后桌面出现「CordiBank 蜂群银行助手」快捷方式，双击启动。

## 三、运行机制

应用启动时按顺序做四件事。

| 步骤 | 行为 |
|---|---|
| 一 | 在随机端口启动后端服务，端口占用时自动顺延 |
| 二 | 把预置 MCP 服务清单写入用户数据目录 |
| 三 | 等待后端健康检查通过 |
| 四 | 创建窗口加载前端界面 |

界面与后端同源，直接访问 `http://127.0.0.1:<端口>`，没有跨域问题，也不需要额外的代理配置。

启动完成后主进程会做一次自检：请求工具清单、走一条真实换汇业务、请求前端首页，结果写进日志。

## 四、实测结果

在 Windows 10 上以打包后的可执行文件运行，进程内自检输出如下。

| 检查项 | 结果 |
|---|---|
| 后端启动 | 随机端口监听成功 |
| 健康检查 | 通过 |
| 工具注册 | 34 个，其中内置 21 个、MCP 外部 13 个 |
| MCP 真实调用 | 100 美元换汇返回 712 元，汇率 7.12 |
| 前端首页 | HTTP 200 |
| 进程数 | 12 个，含 4 个应用进程与 8 个 MCP 子进程 |

## 五、数据存放位置

运行数据不写在安装目录，落在用户目录下的 `CordiBank 蜂群银行助手` 文件夹：

```text
%APPDATA%\CordiBank 蜂群银行助手\
├─ desktop.log            启动日志与自检结果
└─ store\
   ├─ mcp.json            MCP 服务清单
   └─ bank\
      ├─ state.json         账户与账单状态
      ├─ audit.jsonl        审计链
      └─ confirm.key        确认令牌密钥
```

卸载应用不会删除这些数据。需要恢复初始状态时用菜单「文件 → 重置演示数据」。

## 六、MCP 服务如何运行

四个外部服务在开发环境下用系统 `node` 命令拉起，打包后系统不一定装有 Node，因此改用 Electron 自带的 Node 运行时。可执行文件换成 Electron 自身，再设置 `ELECTRON_RUN_AS_NODE=1`，行为与 `node` 一致。

MCP（Model Context Protocol，模型上下文协议）子进程通过 `src/mcp-bootstrap.cjs` 引导。子进程先清掉宿主注入的 `NODE_OPTIONS`，再加载真正的 MCP 服务。`runtime` 源码无需修改。

## 七、环境变量兼容

打包版 Electron 有两个已知限制，应用在主进程启动时做了处理。

**`NODE_OPTIONS` 不受支持。** 某些开发环境会注入 `NODE_OPTIONS`，打包版 Electron 遇到它会直接报错退出。主进程启动时删除该变量并重新拉起自己。

**`ELECTRON_RUN_AS_NODE` 会让程序退化成纯 Node。** 该变量存在时应用不会开界面，同样在启动时清除。

MCP 子进程需要保持纯 Node 模式，由引导脚本负责区分，不会触发重启。

## 八、从源码构建

### 依赖

Node.js 22 或更高。Electron 与 electron-builder 装在 `desktop/` 目录。

```bash
cd desktop
npm install
```

国内网络建议先换镜像源，Electron 二进制与打包工具链都走镜像。

```bash
npm config set registry https://registry.npmmirror.com
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
node node_modules/electron/install.js
```

打包工具链可预先下载到缓存目录，避免打包时卡在网络请求上。

```bash
CACHE="$LOCALAPPDATA/electron-builder/Cache"
mkdir -p "$CACHE"
BASE="https://npmmirror.com/mirrors/electron-builder-binaries"
for item in "winCodeSign-2.6.0/winCodeSign-2.6.0.7z" "nsis-3.0.4.2/nsis-3.0.4.2.7z" "nsis-resources-3.4.1/nsis-resources-3.4.1.7z"; do
  curl -L -o "$CACHE/$(basename "$item")" "$BASE/$item"
done
```

### 开发运行

```bash
npm start
```

该命令先编译 runtime 后端与 web 前端，再启动 Electron。

### 只打包不安装

```bash
npm run pack
```

产物在 `desktop/release/win-unpacked/`，可直接运行 `CordiBank 蜂群银行助手.exe`。

### 生成安装包

```bash
npm run dist
```

产物在 `desktop/release/`。

## 九、目录结构

```text
desktop/
├─ src/
│  ├─ main.cjs           主进程：启动后端、准备清单、管理窗口、自检
│  ├─ preload.cjs        预加载脚本，暴露最小接口
│  └─ mcp-bootstrap.cjs  MCP 子进程引导，清理环境变量后加载服务
├─ scripts/
│  ├─ build-runtime.mjs  编译后端 TypeScript，并复制 package.json
│  ├─ build-web.mjs      构建前端产物
│  └─ make-icon.py       生成应用图标
├─ build/
│  ├─ icon.ico           Windows 图标
│  └─ icon.png           图标预览
└─ package.json          打包配置
```

## 十、已知限制

**应用未做代码签名。** Windows SmartScreen 首次运行会提示「未知发布者」，点「更多信息 → 仍要运行」即可。这是自签名应用的常规表现，不影响功能。

**模型密钥不随包分发。** 应用从环境变量读取 `LLM_API_KEY`。不配置时系统走纯规则模式，六个场景照样能演示，口语化表达的识别率会下降。

**平台限定。** 当前只产出 Windows x64 安装包。macOS 与 Linux 需要在对应系统上执行打包命令，配置本身跨平台通用。
